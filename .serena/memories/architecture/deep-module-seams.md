# Deep module seams

Compoviz's intended feature boundaries are:

- `features/compose-workspace`: `ComposeWorkspaceProvider` / `useComposeWorkspace` own source replacement, configuration reparsing, latest-generation ordering, parser fallback, enrichment, validation/suggestions/AST/YAML derivation, persistence, clear, and YAML download. Exact raw `ComposeState` remains the editing/persistence/YAML source.
- `features/compose-editing`: `useComposeEditing` accepts discriminated `ComposeEdit` intents, commits one complete-state history transition per applied edit, and owns undo/redo (50-transition cap). UI and React Flow callers must not dispatch reducer actions or mutate Compose state directly. Whole-canvas builder cleanup uses the atomic `position-resources` intent; repeated identical positions are unchanged and add no history.
- `features/project-comparison`: `ProjectComparisonProvider` / `useProjectComparison` own simple YAML admission, three-project capacity, identity, immutable projects/findings/counts/summary snapshots, removal, and clear. Capacity is checked before parsing.
- `features/diagram`: `RenderedArchitectureDiagram` accepts DOT, an accessible label, optional overlay, and optional opaque node activation. It owns Graphviz worker lifecycle, stale-result protection, SVG sanitization/insertion/export, native listeners, pan/zoom/fit/reset, and the fixed `docker-compose-diagram.svg` filename. DOT generation stays with callers.
- Build-canvas cleanup: `src/utils/builderLayout.ts` is the pure deterministic Dagre seam for fixed-size, left-to-right, 15px-grid node placement. Cleanup preserves Dagre's X ranks and replaces its Y output with stable compact lanes that align long chains and reuse rows across columns. `VisualBuilder` invokes it explicitly and once on the first Build presentation of a loaded source with no valid saved position; arranged sources and source-less hand-built workspaces are preserved. Both paths persist through one atomic `position-resources` edit and fit the canvas with asymmetric padding that keeps nodes clear of persistent overlays. `src/components/edges/orthogonalPath.ts` is the pure deterministic Manhattan-routing seam: `VisualBuilder` supplies live node rectangles using measured dimensions when available, unrelated blocks are clearance-expanded obstacles, and custom edges retain semantic styles while consuming the shared rounded path. `VisualBuilder` supplies sorted same-source network sibling ids; eligible fan-out edges overlap on one obstacle-checked top-side bus and fall back to individual routes when direction, terminal clearance, or obstacles make bundling unsafe. `stateToFlow` assigns relationship-specific dependency, network, and volume terminal IDs; networks and named volumes provide right-side outputs into adjacent typed inputs on the service's left side, while service dependencies retain a right-side output. `src/utils/builderConnectionGeometry.ts` is the shared direction/spacing seam: builder inputs are left, outputs are right, router fallbacks use those sides, and cleanup reserves 180px between connected ranks for the longest typed leads plus a visible middle run.

- Canonical Compose reads: `ComposeWorkspaceProvider` creates one AST per raw workspace revision; validation, suggestions, VisualBuilder flow conversion, and primary Graphviz generation accept that AST only. Raw `ComposeState` remains authoritative for editing, persistence, and YAML.
- Comparison admission stores a private `{ project, ast }` record per immutable project. Findings and multi-project DOT consume those records; the public snapshot exposes compatible projects plus synchronized `diagramDot`, never the internal AST records.
- Production `normalizeToAST` calls belong only at workspace revision derivation and comparison admission.
